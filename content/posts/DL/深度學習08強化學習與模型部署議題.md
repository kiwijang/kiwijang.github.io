## 前言

最後一章把前面的神經網路接到其他領域: diffusion 可以換用 Transformer，模型可以和搜尋演算法合作，也需要考慮部署大小與評估方式。

這篇依簡報整理各個主題的入口，不把它們當成單一演算法，也不把課堂上的研究推測直接當成定論。

## 1. Diffusion Transformer

DiT 以 Transformer backbone 處理 diffusion 去噪，常在 latent space 把表示切成 patches，配合時間步與條件資訊。

生成影片時還要建模時間與空間關聯。切成時空 token 是一種做法，但不代表所有影片產品都用同一種切法或架構。核心設計可參考 [DiT 論文](https://arxiv.org/abs/2212.09748)。

這邊換掉的是 denoiser 的架構，不是把加噪和採樣流程全部取消。

## 2. 強化學習的基本元素

| 名詞 | 意義 |
| --- | --- |
| Agent | 做決策的主體 |
| Environment | Agent 互動的環境 |
| State／observation | 環境狀態或實際能觀察到的資訊 |
| Action | 採取的動作 |
| Reward | 動作後得到的回饋 |
| Policy | 依資訊選擇動作的規則 |

RL 關心長期累積 reward，不只是每一步拿最高即時分數。State 和 observation 也不一定相同，agent 可能只能看到環境的一部分。

## 3. Q-learning

Q(s,a) 表示在狀態 s 選動作 a 的長期價值估計。常見更新:

```text
Q(s,a) ← Q(s,a) + α[r + γ max_a' Q(s',a') − Q(s,a)]
```

α 是 learning rate，γ 是 discount factor。真正的終止狀態沒有後續價值，bootstrap 項應為 0；時間限制截斷與環境終止則要依任務定義分開處理。

Q-table 適合有限且較小的 state-action space。DQN 改用網路近似 Q，通常還需要 replay buffer、target network 等穩定機制，不是只換成 Dense layers 就完成。

## 4. Exploration、Bandit 與 UCB

一直選目前最好的動作，可能錯過尚未試過的更好選擇。一直探索，又會犧牲目前能得到的 reward。

ε-greedy 用一部分機率探索，其他時候使用目前較好的選擇。Bandit 的 UCB 可以把平均報酬與不確定性 bonus 結合:

```text
score_i = mean_reward_i + c sqrt(log(N)/n_i)
```

常見實作會先處理尚未被選過的選项，避免除以 0。c 的尺度和 reward 範圍有關，不是所有問題固定為同一個數字。

## 5. MCTS 與 AlphaGo

MCTS (Monte Carlo Tree Search) 反覆做四個步驟:

1. Selection: 使用價值與探索規則往下選。
2. Expansion: 加入尚未展開的動作。
3. Simulation／evaluation: 模擬或使用模型評估結果。
4. Backup: 把結果沿路回傳，更新次數與價值。

MCTS 的 backup 是更新搜尋統計，不是神經網路的梯度反向傳播。對手回合也要統一價值的玩家視角，不能直接把每個節點都當成自己最大化同一個分數。

原始 AlphaGo 結合 policy、value、rollout 與 tree search；AlphaZero 使用自我對弈學習，再和搜尋合作。Zero 不表示沒有遊戲規則、模型架構或其他人為設計，只是不用人類棋譜當監督訓練起點。

簡報的棋盤圖示是搜尋過程示例。本篇保留四步驟與模型分工，不根據抽出的文字猜測每一步棋的位置。

## 6. 訓練紀錄與 callbacks

EarlyStopping 看監控指標決定停止；ModelCheckpoint 保存模型；TensorBoard 協助查看訓練紀錄。功能定義見 [Keras callbacks](https://keras.io/api/callbacks/)。

```python
from tensorflow import keras

callbacks = [
    keras.callbacks.EarlyStopping(
        monitor="val_loss", patience=5, restore_best_weights=True
    ),
    keras.callbacks.ModelCheckpoint(
        "best.keras", monitor="val_loss", save_best_only=True
    ),
    keras.callbacks.TensorBoard(log_dir="logs/experiment-01"),
]
# 使用方式: model.fit(..., validation_data=(x_val, y_val), callbacks=callbacks)
```

這是補充設定片段，必須真的提供 validation data 才有 val_loss。Checkpoint、資料切分與實驗設定要一起保存，才方便重現。

## 7. 為什麼大模型仍可能泛化？

簡報討論資料結構、inductive bias、優化路徑與 over-parameterization。這些是理解訓練與泛化的研究方向，不是一條「參數越多必定越好」定律。

能擬合隨機標籤的模型，也可能在真實資料上學到有用規律。因此單靠 training error 或參數數量，不能解釋全部泛化行為，見 [Rethinking Generalization](https://arxiv.org/abs/1611.03530)。

同樣地，一般非凸最佳化很難，不表示每個實際網路都會失敗；特定實驗成功，也不代表 loss surface 完全沒有局部極小值。

## 8. 剪枝與知識蒸餾

Pruning 可刪除或遮蔽部分權重，再做 fine-tuning。Unstructured sparsity 不一定自動加速一般硬體，因為稠密運算可能仍照常執行。部署還要量測檔案大小、延遲、記憶體與 accuracy。

Lottery Ticket Hypothesis 探索部分子網路與初始化的關係，是另一種研究方向，不能直接套成所有模型都能保留固定百分比參數。

Knowledge distillation 讓 student 學 teacher 的輸出關係，例如溫度調整後的 soft targets，搭配真實標籤 loss；也可以設計 logits 或 feature 對齊。它不只限定 MSE，見 [知識蒸餾論文](https://arxiv.org/abs/1503.02531)。

## 9. 偏見與部署回饋循環

簡報把 bias 來源分成問題定義、資料、建模評估與部署。可以依這四個位置檢查:

- Target 是否只是想衡量概念的不完整代理指標？
- 資料是否缺少某些群體或環境？
- 整體平均分數是否掩蓋子群體失敗？
- 部署行動會不會反過來改變後續蒐集的資料？

例如用醫療支出代表需求，是概念上的代理指標問題；增加某地巡查後記錄更多事件，則可能形成回饋循環。這些是風險機制的例子，不是在斷言每個特定機構都有同樣行為。
