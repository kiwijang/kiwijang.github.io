## 前言

模型可以跑，不代表模型就會學好。這篇整理訓練時常調整的幾件事: loss、activation、初始化、optimizer 與 regularization。

## 1. 先決定任務，再決定輸出

| 任務 | 輸出 | 常見 activation | 常見 loss |
| --- | --- | --- | --- |
| 單一數值迴歸 | 一個實數 | Linear | MSE／MAE |
| 二元分類 | 正類機率 | Sigmoid | Binary cross-entropy |
| C 類、每筆只有一類 | C 個機率，總和為 1 | Softmax | Categorical cross-entropy |
| C 個標籤，可同時成立 | C 個機率 | 各自 sigmoid | 各標籤 binary cross-entropy |

多元分類和多標籤分類不要混淆。例如一張圖片既有貓又有車，就不能硬要求所有標籤機率相加為 1。

也可以直接輸出 logits，配合 `from_logits=True` 的 loss。這時不要又先做 softmax／sigmoid，再告訴 loss 輸入是 logits。

## 2. Cross-entropy 怎麼衡量預測？

單筆二元分類的 loss 為:

```text
L = −[y log(p) + (1−y) log(1−p)]
```

`y=1` 時，希望 p 接近 1；`y=0` 時，希望 p 接近 0。用 log 可以把多筆 likelihood 的乘積轉成加總，再用負號改成最小化問題。

多元分類的 one-hot target 為 `L = −Σc y_c log(p_c)`，也就是正確類別機率越小，懲罰越大。整個 batch 可以再取平均。

Softmax 將 logits 轉成機率分布。實作通常先減掉最大 logit，再計算 exp，避免數值溢位；不必自行用不穩定的公式重寫框架 loss。

## 3. 梯度消失、爆炸與 dying ReLU

Backpropagation 會連續乘上各層的 Jacobian。尺度逐層縮小，可能讓前面層幾乎不更新；逐層放大，則可能造成更新失控與 NaN。

Sigmoid 的導數最大為 0.25，飽和時更接近 0。但完整梯度還包含權重，不能只用 activation 導數判定所有網路的梯度。

| 問題 | 可檢查的方向 |
| --- | --- |
| 梯度很小 | Activation、初始化、深度、資料尺度 |
| 梯度過大／NaN | Learning rate、梯度 norm、數值範圍 |
| ReLU 長期輸出 0 | 輸入分布、learning rate、Leaky ReLU |

ReLU、Leaky ReLU、GELU、SiLU 各有不同形狀，不必把它們硬分成只能處理圖片或文字的函式。

## 4. He 初始化與 normalization

使用 ReLU 時，He 初始化的常見尺度為 `Var(w) ≈ 2 / fan_in`。例如 fan-in 為 80，參考變異數就是 `0.025`，和簡報的實驗相呼應。

這是建立良好初始尺度的方式，不是訓練全程梯度穩定的保證。不同 activation、架構和 fan 計算方式，需要配合適當設定。

Batch normalization 會依 batch 統計量正規化，再套用可學習的縮放與平移。因此最終輸出不一定剛好均值 0、變異數 1；訓練與推論使用統計量的方式也不同。

梯度裁剪則限制過大的梯度。Value clipping 逐元素裁剪；global norm clipping 按整體 norm 縮放，較能保留整體方向。

## 5. Learning rate、batch 與 optimizer

一個 epoch 通常是走過訓練資料一次；一次 step 是一次更新。Batch size 決定每次用多少資料估計梯度，optimizer 名稱叫 SGD，也能以 mini-batch 執行。

| Optimizer | 核心做法 |
| --- | --- |
| SGD | 使用當次梯度更新 |
| Momentum | 累積歷史梯度方向 |
| RMSprop | 利用平方梯度的歷史尺度調整更新 |
| Adam | 結合一、二階矩估計與 bias correction |
| AdamW | 將 weight decay 與 Adam 的梯度更新解耦 |

這些方法不保證避開所有局部極小值。簡報把 AdamW 類比成 Adam 加 L2；更精確地說，它使用 decoupled weight decay，對 Adam 而言不等同把 L2 項直接加進 loss，見 [Keras AdamW](https://keras.io/api/optimizers/adamw/)。

Learning rate schedule 可以使用 step decay、exponential decay 或 cosine decay；warmup 則先逐步提高 learning rate。每次只調一個主要因素，才比較容易看出影響。

## 6. Overfitting 與 regularization

Training loss 下降，validation loss 卻逐漸上升，是值得檢查的 overfitting 訊號。模型可能記住背景或特定樣本，而不是學到想要的規律。

簡報整理了以下做法:

- L1／L2: 在目標加入參數懲罰。
- Dropout: 訓練時隨機遮蔽部分輸出，降低固定依賴。
- Early stopping: 依 validation 指標停止。
- Data augmentation: 增加合理的資料變化。
- Ensemble: 組合多個模型結果。
- Label smoothing: 避免 target 永遠是極端 one-hot。
- 調整模型容量、取得更多有代表性的資料。

Dropout rate 0.3 是各單元的遮蔽機率，不保證每次剛好關掉 30%。Augmentation 也必須保持標籤合理，例如數字翻轉不一定仍是同一個數字。

L1 含絕對值，在 0 附近不可微；不要把所有正則化一律解釋成「讓 loss surface 變平滑」。泛化是否改善，仍要看驗證結果。

## 7. 實驗時先看什麼？

先檢查資料切分、輸入尺度與 label，再確認輸出層和 loss 配對。接著看 learning curve、梯度尺度與參數更新，最後再比較不同 optimizer 或正則化。

簡報練習涵蓋房價、垃圾郵件、CIFAR-10、醫學文章分類與梯度實驗。不同任務要分別選指標，不能只拿 accuracy 比較所有模型。
