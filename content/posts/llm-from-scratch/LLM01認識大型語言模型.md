## 文字接龍，怎麼成為語言模型？

輸入「今天下雨，出門記得帶」，我們可能想到「傘」。語言模型做的是類似的預測，但它輸出的是整個詞彙表的分數，再透過解碼方式選出下一個 token。

本篇對應原專案 Chapter 1。這一章建立觀念，不急著寫網路層；後續每一段程式，都可以回頭對照這張學習地圖。

## 1. 模型真正預測的是 token

Token 是 tokenizer 切分出來的單位，可能是字、詞的一部分、空白或其他片段。不能直接說「一個中文字就是一個 token」，也不能把 token 數當成字數。

假設一段文字被轉成 `t1, t2, ..., tn`，自迴歸語言模型把序列機率拆成：

```text
P(t1, ..., tn) = P(t1) × P(t2 | t1) × ... × P(tn | t1, ..., t(n−1))
```

每一步依賴前面的內容。把新產生的 token 接回輸入，再做下一次預測，就得到一段長文字。

「一次預測一個」描述的是生成流程。訓練時已有完整序列，可以透過 causal mask 同時計算多個位置的預測；不能因此讓前面的位置偷看後面的答案。

## 2. 三個容易混在一起的東西

| 名稱 | 指的是什麼 | 類比 |
| --- | --- | --- |
| 架構 | 運算如何連接、維度多大 | 一套可調整的機器結構 |
| 參數／權重 | 訓練調整的數值 | 機器目前的設定 |
| 訓練資料與目標 | 用什麼例子、如何計算錯誤 | 練習題與評分規則 |

把 GPT 架構寫出來，只表示前向計算可以運作。隨機初始化的模型還沒學到語言規律，即使生成程式會輸出字串，也不能當成已完成訓練。

載入預訓練權重則是另一條路：沿用既有學習成果，再做推論或微調。這與自己從隨機權重預訓練，是兩種不同的實驗。

## 3. 預訓練與微調分別改變什麼？

預訓練可以直接從一般文字建立「前文 → 下一個 token」的樣本，不需要人工為每個位置標註答案，所以常稱為自監督學習。沒有人工標籤，不代表沒有訓練標的。

分類微調會使用文字和類別，例如簡訊及垃圾訊息標記。模型最後輸出的是各類別分數。

指令微調會使用指令與示範回答。輸出仍是一連串 token，但資料格式讓模型接觸「看到這種要求，應該如何回答」的範例。

這些階段都可能更新權重；差別在資料分布、輸出形式與 loss 的設計。推論時在提示放入範例，通常不會更新模型參數，應和微調分開理解。

## 4. 為什麼選 GPT 類結構？

本系列的主角是 decoder-only Transformer。它透過 causal self-attention 整合目前位置以前的資訊，適合逐步延伸文字。

Encoder 類模型常用雙向上下文建立表示；encoder-decoder 類模型則把來源編碼和目標生成分開。這些是不同的結構選擇，不能把所有 Transformer 都視為同一種 GPT。

從零實作的好處，是能看見資料在每一層如何改變。先理解小模型的矩陣運算，再閱讀大型模型時，比較容易辨認哪些是核心流程、哪些是效率或訓練上的改進。

## 5. 七章串起來的工作流程

```text
原始文字 → tokenizer → token IDs → embedding
       → causal Transformer → vocabulary logits
       → next-token loss → 反向傳播與參數更新

預訓練權重 → 分類微調／指令微調 → 任務評估
```

前半段建立語言模型，後半段讓既有模型適應任務。各階段都需要驗證，不能只用一段看起來通順的回答判斷學習成功。

## 6. 練習：把「理解」拆成可檢查的問題

試著用自己的話回答：

1. 為什麼訓練文字能自己提供下一個 token 的標籤？
2. 架構完全相同的兩個模型，回答為什麼可能差很多？
3. 使用者更改提示和開發者執行微調，哪一個會更新參數？

可以用這三點核對：標籤來自序列位移；權重與訓練歷程可能不同；一般提示推論不會執行梯度更新。
