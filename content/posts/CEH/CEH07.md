## 前言

理解木馬、病毒、蠕蟲與無檔案威脅，建立靜態與動態分析的基本觀念。

這篇依 EC-Council 教材 `module07.pdf` 整理，聚焦可確認的主要觀念，並非逐頁翻譯或完整操作手冊。各節頁碼指 **PDF 檔案內頁次**，包含封面及空白頁，不是書中印刷頁碼。實際測試以取得授權的範圍為前提。

## 1. 先用行為分辨惡意程式

教材介紹木馬（Trojan）、病毒（Virus）、蠕蟲（Worm）與勒索軟體（Ransomware）。木馬強調偽裝或誘使執行，病毒與宿主檔案的感染相關，蠕蟲著重自我傳播，勒索軟體則以勒索目的與破壞／限制存取的行為理解。這些分類角度可能重疊，不能只憑名稱就推定全部能力。

*來源：本章 PDF 第 4–96 頁；以摘要及觀念解說重新整理。*

## 2. 持續性威脅與無檔案威脅

APT 強調針對性與持續活動。無檔案（Fileless）威脅則提醒我們，惡意行為可能利用記憶體、指令碼或既有系統工具，未必留下典型的獨立執行檔。不能只因找不到陌生 EXE，就認為系統安全。

*來源：本章 PDF 第 15–20、97–114 頁；以摘要及觀念解說重新整理。*

## 3. 靜態分析：先不執行樣本

靜態分析查看檔案雜湊、字串、格式、匯入資訊或程式結構，形成後續分析假設。教材涵蓋 PE、ELF、Office 文件與 PDF 等格式。雜湊可協助比對同一檔案，但檔案一旦改變，雜湊也可能不同；字串存在也不等於一定執行過對應行為。

*來源：本章 PDF 第 130–176 頁；以摘要及觀念解說重新整理。*

## 4. 動態分析：觀察實際行為

動態分析觀察樣本執行後的程序、連線、檔案、登錄、服務與其他系統變化。教材先談準備測試環境，再介紹監控方式。靜態與動態分析互相補充；一次沒有觀察到惡意行為，仍可能是觸發條件未滿足。

*來源：本章 PDF 第 177–218 頁；以摘要及觀念解說重新整理。*

## 5. 把分析結果連到防護與回應

對策包括更新、限制執行、使用者訓練與端點偵測回應。偵測線索應與環境、時間及行為一起判讀，避免只靠單一特徵下結論。教材也談 AI 與惡意程式；本文不把教材中的能力敘述直接當成已驗證的產品效能。

*來源：本章 PDF 第 249–266 頁；以摘要及觀念解說重新整理。*

## 重要名詞

| 名詞 | 這篇的理解重點 |
| --- | --- |
| Static Analysis | 不執行樣本，分析其內容與結構。 |
| Dynamic Analysis | 在受控環境觀察執行行為。 |
| EDR | 端點偵測與回應。 |

## 理解用例（本文自擬）

某文件裡有可疑網址，靜態分析先將它列為線索；動態分析再確認是否發起連線、由哪個程序觸發，以及是否建立持續性。單看網址字串不足以還原完整事件。

這個例子用於解釋觀念，不是教材案例、實測結果或作者經歷。
