## 前言

區分應用層與網路層的劫持，理解 Session Token、重放與固定工作階段的風險。

這篇依 EC-Council 教材 `module11.pdf` 整理，聚焦可確認的主要觀念，並非逐頁翻譯或完整操作手冊。各節頁碼指 **PDF 檔案內頁次**，包含封面及空白頁，不是書中印刷頁碼。實際測試以取得授權的範圍為前提。

## 1. 登入成功之後，還需要保護什麼？

Session 讓系統在多次互動之間維持狀態。劫持風險不只來自知道密碼：若攻擊者取得可用的 Session 識別資訊，也可能冒用已登入狀態。教材區分應用層與網路層，前者常與網站的 Token／Cookie 有關，後者則涉及連線封包與協定狀態。

*來源：本章 PDF 第 4–15 頁；以摘要及觀念解說重新整理。*

## 2. Token 的產生、傳遞與保存

教材討論側錄、可預測的識別值及其他取得 Token 的途徑，也介紹重放。閱讀時可以依序確認：識別值是否難以猜測、是否透過受保護的通道傳送，以及是否被不當暴露。登入驗證強，不代表登入後的 Token 一定得到同等保護。

*來源：本章 PDF 第 16–29 頁；以摘要及觀念解說重新整理。*

## 3. 劫持與固定工作階段的差別

重放（Replay）利用已取得的有效資訊；Session Fixation 則是讓受害者使用攻擊者事先知道或指定的 Session 識別值。兩者都涉及識別值的生命週期，但問題發生的位置不同。教材同時介紹其他應用層攻擊，本篇只保留可確認的概念。

*來源：本章 PDF 第 27–38 頁；以摘要及觀念解說重新整理。*

## 4. 網路層要理解序號與狀態

TCP 通訊包含狀態及序號等機制，因此網路層劫持需要連同協定行為理解。它與複製網站 Cookie 的情境不同，不能直接混成同一種攻擊。教材中的封包示意用來說明風險，本篇不推定所有環境都能依相同方式劫持。

*來源：本章 PDF 第 39–55 頁；以摘要及觀念解說重新整理。*

## 5. 防護要涵蓋整個 Session 生命週期

本章從偵測、傳輸保護、驗證與相關安全機制討論對策。本文依這些概念整理查核方向：產生識別值、登入後的狀態轉換、使用期間保護，以及過期與撤銷。真正的防護需依應用與通訊協定設計，不能只靠一個設定。

*來源：本章 PDF 第 56–77 頁；以摘要及觀念解說重新整理。*

## 重要名詞

| 名詞 | 這篇的理解重點 |
| --- | --- |
| Session Token | 代表或連結某次工作階段的識別資訊。 |
| Replay | 再次使用已取得的有效資訊。 |
| Session Fixation | 讓使用者採用攻擊者事先知道的工作階段識別值。 |

## 理解用例（本文自擬）

使用者已啟用多因素登入，但有效的登入 Token 若遭竊取，仍可能讓他人冒用狀態。因此登入流程與登入後的狀態管理，都需要分別檢查。

這個例子用於解釋觀念，不是教材案例、實測結果或作者經歷。
