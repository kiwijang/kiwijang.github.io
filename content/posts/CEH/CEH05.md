## 前言

分清楚弱點識別、分類、評分與實際風險，把掃描結果整理成可追蹤的修復工作。

這篇依 EC-Council 教材 `module05.pdf` 整理，聚焦可確認的主要觀念，並非逐頁翻譯或完整操作手冊。各節頁碼指 **PDF 檔案內頁次**，包含封面及空白頁，不是書中印刷頁碼。實際測試以取得授權的範圍為前提。

## 1. 弱點不只有程式漏洞

本章先介紹弱點類型，包含設定、存取控制、軟體與管理相關問題。評估時不能只查有沒有已知漏洞編號；預設帳密、不必要服務或錯誤設定，也可能讓系統暴露風險。

*來源：本章 PDF 第 5–15 頁；以摘要及觀念解說重新整理。*

## 2. CVE、CWE 與 CVSS 各有用途

CVE 用於識別公開揭露的特定弱點，CWE 用於分類弱點類型，CVSS 則提供嚴重度評分框架。NVD 是教材介紹的弱點資料來源之一。這些資料可協助溝通與分析，但編號不等於已確認本機受影響，嚴重度也不等於組織自己的修復優先序。

*來源：本章 PDF 第 16–21 頁；以摘要及觀念解說重新整理。*

| 項目 | 回答的問題 | 不能直接推出什麼 |
| --- | --- | --- |
| CVE | 正在談哪個公開弱點？ | 本機一定受影響 |
| CWE | 屬於哪類弱點？ | 特定部署已遭攻擊 |
| CVSS | 依評分條件有多嚴重？ | 組織必須採用相同修復順序 |

## 3. 弱點管理是一個循環

教材以生命週期說明資產與弱點的識別、評估、處置與後續驗證。完成掃描之後，還需要指定負責人、安排修復、再次檢查結果。若只交付掃描清單，沒有確認問題是否消失，就無法知道風險是否真的降低。

*來源：本章 PDF 第 22–30 頁；以摘要及觀念解說重新整理。*

## 4. 掃描方式決定能看見什麼

內部與外部、具憑證與不具憑證等掃描方式，觀察角度不同。具憑證掃描能利用授權資訊深入檢查，但仍需要控制權限與資料處理。工具也可能產生誤報或漏報，重要發現應核對版本、設定與證據。

*來源：本章 PDF 第 31–45 頁；以摘要及觀念解說重新整理。*

## 5. 報告要讓修復工作可以執行

弱點報告需要描述受影響資產、問題、證據、可能影響與改善方式，並區分管理摘要與技術細節。對修復團隊而言，能重現與複測的資訊，比只有一個高分標籤更有幫助。

*來源：本章 PDF 第 72–76 頁；以摘要及觀念解說重新整理。*

## 重要名詞

| 名詞 | 這篇的理解重點 |
| --- | --- |
| CVE | 特定公開弱點的識別。 |
| CWE | 弱點種類的分類。 |
| CVSS | 弱點嚴重度評分框架；需要連同版本與評分條件解讀。 |

## 理解用例（本文自擬）

兩個服務被標為相同嚴重度，其中一個只在隔離測試區使用，另一個處理對外會員登入。修復排序仍須加入曝露程度、資料敏感性與既有控制，不能只依分數排序。

這個例子用於解釋觀念，不是教材案例、實測結果或作者經歷。

## 課堂照片補充：把弱點資訊整理成可核對的判斷

本節依 `4to6` 的 Q02 白板整理；[來源對照表](./CEH實作與資源.md)保留原檔名。照片列出 MSRC、VMware Security Advisories、CVE、CVSS、NVD、CWE、CVE Details 與 Exploit-DB，但沒有特定弱點編號、掃描結果或成功利用畫面。

### 這些名稱不能互相替代

| 來源／名詞 | 應回答的問題 | 記錄時注意 |
| --- | --- | --- |
| 廠商安全公告 | 哪些產品版本受影響？修補或緩解方式是什麼？ | 以公告修訂時間、版本與適用條件為準；照片中的 MSRC 是 Microsoft 入口。 |
| CVE | 我們討論的是哪一筆已公開識別的弱點？ | 編號是識別用途，本身不是風險分數或修補證明。 |
| CVSS | 在指定評分版本與向量下，技術嚴重性如何表達？ | 記分數也記版本、向量與評分來源；分數不直接等於組織修復優先序。 |
| CWE | 根本弱點屬於哪一類設計或實作問題？ | 是弱點類型分類，不是另一個 CVE 編號；範圍也不限於某種程式語言。 |
| NVD | 可查哪些弱點分析與參考資訊？ | 與廠商公告交叉核對，未提供的欄位留空，不自行補分數。 |
| CVE Details | 是否有方便彙整的第三方查詢介面？ | 第三方整理不能取代廠商對版本與修補的說明。 |
| Exploit-DB | 是否有公開的利用研究或概念驗證可供閱讀？ | 有程式碼不表示自己的設備符合條件，更不等於已驗證可利用。 |

可查閱 [MSRC Update Guide](https://msrc.microsoft.com/update-guide)、[CVE 官方介紹](https://www.cve.org/About/Overview)、[CWE 官方介紹](https://cwe.mitre.org/about/index.html)與 [FIRST CVSS](https://www.first.org/cvss/)。CVE／MSRC 部分入口需要 JavaScript；這次核對入口，沒有登入或操作查詢介面。CWE 與 CVSS 的用途另依官方說明核對。

### 延伸練習：先做一份版本與證據表

以下是依白板概念整理的練習，**不是照片中已完成的實驗**。從自己管理的測試軟體與其廠商公告開始，不預填任意 CVE 或分數。

1. 記錄產品、實際安裝版本、平台與功能設定；版本不明就標「尚未確認」。
2. 找到對應廠商公告，保存網址、公告日期、修訂日期與受影響版本條件。
3. 若公告附 CVE，再交叉查詢；若有 CVSS，抄錄完整版本、向量及來源，保留來源不同的評分。
4. 將「版本符合公告條件」「功能可被觸及」「已確認修補」分開記錄。掃描命中可作為線索，不直接填成成功入侵。
5. 規劃修補、重新檢查與例外追蹤；無法核對的條件保留為待確認。

| 紀錄欄位 | 本次應填的證據 |
| --- | --- |
| 資產與版本 | 實際版本資訊與取得時間 |
| 廠商公告／CVE | 來源網址、版本範圍及對應依據 |
| CWE／CVSS | 僅記來源明列的分類、評分版本、分數及向量 |
| 實際曝露與影響 | 所需權限、啟用功能、網路可達性與業務影響 |
| 處置與複查 | 修補版本、完成時間、複查結果與剩餘疑問 |

Q11 的白板另外畫出弱點掃描、Metasploit 與模組／參數的關係，可用來理解評估到驗證是不同階段。它沒有清楚的模組名稱、完整參數或結果，所以這裡不拼出攻擊命令，也不記成成功利用。此批照片仍未補齊 Module 05 的手冊實驗正文。
