## 前言

從 Apache、IIS、Nginx 的角色理解服務曝露、錯誤設定與修補管理。

這篇依 EC-Council 教材 `module13.pdf` 整理，聚焦可確認的主要觀念，並非逐頁翻譯或完整操作手冊。各節頁碼指 **PDF 檔案內頁次**，包含封面及空白頁，不是書中印刷頁碼。實際測試以取得授權的範圍為前提。

## 1. 先分清楚伺服器與應用程式

Web Server 負責接收與處理網頁相關請求，可能再與應用及其他服務合作。教材介紹 Apache、IIS 與 Nginx 架構。辨識某個伺服器產品，可以幫助確認待檢查元件，但不能單憑產品名稱就認定它一定存在特定弱點。

*來源：本章 PDF 第 4–25 頁；以摘要及觀念解說重新整理。*

## 2. 設定與路徑處理也是攻擊面

教材列出多種攻擊，包含目錄穿越、設定問題、快取與 HTTP 相關風險。共同觀念是：外部請求的路徑、標頭與內容，會經過伺服器及其他元件的解析；若存取限制或處理邏輯有落差，可能影響檔案或回應。

*來源：本章 PDF 第 26–51 頁；以摘要及觀念解說重新整理。*

## 3. 從資訊蒐集到弱點確認

本章以方法論串起資訊蒐集、服務辨識、目錄與資源探索、弱點確認等工作。已知版本與可見頁面是線索，仍需核對設定、修補與實際影響。管理介面是否曝露，也應和一般網站功能分開評估。

*來源：本章 PDF 第 52–98 頁；以摘要及觀念解說重新整理。*

## 4. 基本防護來自持續的服務管理

教材討論減少不必要功能、保護管理入口、強化帳號及權限、監控異常與設定安全通訊。這些措施互相補足：隱藏版本資訊可能降低直接曝露，但不能代替修補或正確存取控制。

*來源：本章 PDF 第 99–123 頁；以摘要及觀念解說重新整理。*

## 5. 修補之後要確認服務仍正常

Patch Management 涉及更新、部署與維護。本篇依教材概念整理為：先盤點受影響元件，評估更新，安排部署，再確認問題與正常功能。網站可能包含多個相依元件，不能只更新首頁可見的伺服器軟體。

*來源：本章 PDF 第 124–129 頁；以摘要及觀念解說重新整理。*

## 重要名詞

| 名詞 | 這篇的理解重點 |
| --- | --- |
| Web Server | 處理網頁服務請求的伺服器元件。 |
| Directory Traversal | 利用路徑處理問題存取預期範圍之外的資源。 |
| Patch Management | 管理修補評估、部署及後續確認。 |

## 理解用例（本文自擬）

同一個網站可能有反向代理、網頁伺服器與應用程式。若管理介面原本只應內部使用，應檢查實際路由與存取規則；不能只因主頁正常顯示，就認為管理入口也受到保護。

這個例子用於解釋觀念，不是教材案例、實測結果或作者經歷。
