## 前言

以共享責任與身分權限為主軸，串起雲端服務、設定曝露與容器風險。

這篇依 EC-Council 教材 `module19.pdf` 整理，聚焦可確認的主要觀念，並非逐頁翻譯或完整操作手冊。各節頁碼指 **PDF 檔案內頁次**，包含封面及空白頁，不是書中印刷頁碼。實際測試以取得授權的範圍為前提。

## 1. 服務模式改變管理責任

教材介紹 IaaS、PaaS、SaaS、部署模式與共享責任。使用的服務層次不同，客戶與供應商管理的範圍也不同。上雲之後仍要確認帳號、資料、應用與設定由誰負責，不能只因基礎設施由供應商管理，就假設全部安全工作都已交付。

*來源：本章 PDF 第 5–35 頁；以摘要及觀念解說重新整理。*

## 2. 容器與編排擴大了管理對象

本章介紹容器、相關架構與安全。映像、執行中的工作負載、主機、網路與管理介面彼此相關。部署成功只代表程式能運作，不代表映像來源、權限、機密資料與管理介面都符合預期。

*來源：本章 PDF 第 36–60 頁；以摘要及觀念解說重新整理。*

## 3. 雲端威脅常與身分和設定交織

教材涵蓋資料曝露、帳號與憑證、設定、API、容器及其他風險。分析時要把「誰取得哪種權限」和「資源實際允許什麼操作」連在一起。可從網路連到資源，不等於有權讀取內容；反過來，有憑證也不代表權限範圍合理。

*來源：本章 PDF 第 61–125 頁；以摘要及觀念解說重新整理。*

## 4. 不同供應商要用各自的模型驗證

本章分別介紹 AWS、Azure、Google Cloud 與容器評估。各平台的資源、身分與權限模型不同，可以借用共同問題意識，但不能把某平台的命令或角色名稱直接套到另一平台。本文以閱讀與防禦觀念整理，不還原利用流程。

*來源：本章 PDF 第 126–287 頁；以摘要及觀念解說重新整理。*

## 5. 持續檢查配置、權限與紀錄

教材討論雲端控制層、IAM、監控、容器與 Serverless 等安全工作。雲端資源變動快，因此安全檢查需要能隨部署持續進行。發現問題後也要確認修復是否真的改變有效權限或資源曝露。

*來源：本章 PDF 第 288–341 頁；以摘要及觀念解說重新整理。*

## 重要名詞

| 名詞 | 這篇的理解重點 |
| --- | --- |
| Shared Responsibility | 依服務與安排分配客戶、供應商的責任。 |
| IAM | 身分與存取管理。 |
| Container | 封裝應用與相依內容的執行方式；仍有主機與管理邊界。 |

## 理解用例（本文自擬）

某個儲存空間的資料沒有變動，但存取政策改成允許更廣的對象，風險就可能改變。雲端評估除了檢查檔案內容，也要追蹤身分、政策與資源設定。

這個例子用於解釋觀念，不是教材案例、實測結果或作者經歷。
