## 前言

從信任邊界、驗證與授權，到 API 與事件通知，整理 Web 應用的主要安全問題。

這篇依 EC-Council 教材 `module14.pdf` 整理，聚焦可確認的主要觀念，並非逐頁翻譯或完整操作手冊。各節頁碼指 **PDF 檔案內頁次**，包含封面及空白頁，不是書中印刷頁碼。實際測試以取得授權的範圍為前提。

## 1. 應用安全要看資料如何跨越邊界

教材先介紹應用架構、元件與 Web Services。瀏覽器、應用、資料庫與外部服務的互動，形成多個信任邊界。分析時應追蹤資料從哪裡進入、在哪裡被處理，以及哪個元件負責檢查，而不只看畫面上的輸入框。

*來源：本章 PDF 第 5–13 頁；以摘要及觀念解說重新整理。*

## 2. 輸入、輸出與授權是不同檢查點

本章涵蓋注入、XSS、XXE、SSRF、Session 與其他威脅。注入涉及把資料交給解譯器時的邊界；XSS 與瀏覽器執行內容有關；SSRF 涉及伺服器代為發送非預期請求。是否能讀取某個物件，還需要獨立的授權判斷，不能用「已登入」代替。

*來源：本章 PDF 第 14–100 頁；以摘要及觀念解說重新整理。*

## 3. 測試應追蹤狀態與業務流程

教材的方法論包含資訊蒐集、輸入位置、驗證、授權與 Session 等測試。除了單次請求，也要思考前後步驟：某項操作的必要條件，是否真的由伺服器確認。工具可以協助收集請求，但需要理解業務規則才能判定問題。

*來源：本章 PDF 第 101–237 頁；以摘要及觀念解說重新整理。*

## 4. API 與 Webhook 的方向不同

API 提供系統互動介面；Webhook 則在事件發生後向接收端發送通知。本章討論身分、授權、輸入、流量限制及 Webhook 的來源驗證、時間與重複事件。接收端不能只看內容格式正確，就認定事件可信或只會送達一次。

*來源：本章 PDF 第 238–288 頁；以摘要及觀念解說重新整理。*

## 5. 測試與防護要互相配合

教材介紹 SAST、DAST、Fuzz Testing 與多種防禦。靜態分析檢查程式與結構，動態測試觀察運作中的應用；兩者觀察範圍不同。防護仍需落實在設計、程式與設定，不能只等部署後的設備擋住所有問題。

*來源：本章 PDF 第 289–367 頁；以摘要及觀念解說重新整理。*

## 重要名詞

| 名詞 | 這篇的理解重點 |
| --- | --- |
| Authentication／Authorization | 驗證你是誰／判斷你能做什麼。 |
| SSRF | 伺服器遭誘導發送非預期請求。 |
| Webhook | 由事件觸發、發送到接收端的通知。 |

## 理解用例（本文自擬）

訂單付款通知可能因重試而送達兩次。接收端除了驗證通知來源，也需辨識同一事件，避免重複出貨。這個例子說明來源可信與事件處理正確，是兩個不同問題。
