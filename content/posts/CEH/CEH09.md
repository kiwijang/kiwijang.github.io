## 前言

從冒充、釣魚、實體尾隨與行動裝置誘導，理解人的流程如何成為攻擊入口。

這篇依 EC-Council 教材 `module09.pdf` 整理，聚焦可確認的主要觀念，並非逐頁翻譯或完整操作手冊。各節頁碼指 **PDF 檔案內頁次**，包含封面及空白頁，不是書中印刷頁碼。實際測試以取得授權的範圍為前提。

## 1. 攻擊的入口可能是一段互動

社交工程（Social Engineering）利用人的信任、習慣與情境誘導取得資訊或促成行動。教材以人、電腦與行動裝置等方式分類。理解時要看對方要求你做什麼，以及這個要求如何繞過原本的驗證與授權流程。

*來源：本章 PDF 第 4–12 頁；以摘要及觀念解說重新整理。*

## 2. 冒充與實體存取

教材介紹冒充、電話誘導、偷看、翻找棄置資訊與尾隨等方法。共同問題是把表面的熟悉感、權威或急迫性，直接當成對方有權取得資訊的證明。工作流程應提供可使用的核對方法，而不只要求員工提高警覺。

*來源：本章 PDF 第 13–24 頁；以摘要及觀念解說重新整理。*

## 3. 釣魚訊息與身分盜用

釣魚可能誘使使用者點開網站、交出憑證或執行檔案。本章也討論社群冒充、身分盜用，以及 AI 生成影像或聲音的冒充情境。辨識重點不能只放在文法錯誤或聲音是否熟悉，仍應核對來源與操作目的。

*來源：本章 PDF 第 25–59 頁；以摘要及觀念解說重新整理。*

## 4. 行動裝置與 QR Code 的誘導

惡意或偽裝應用程式、簡訊與 QR Code 登入情境，都可能被利用。QR Code 只是承載資訊的形式，不能因為方便掃描就視為可信。若操作會授權登入、交付憑證或安裝程式，必須先了解自己授權的是什麼。

*來源：本章 PDF 第 60–67 頁；以摘要及觀念解說重新整理。*

## 5. 防護需要可執行的核對與通報

教材討論訓練、實體管理、釣魚防護與稽核。可以把防護分成辨識、核對與通報：辨識不尋常要求，透過既有可信管道核對，再讓疑似事件能被回報。若核對流程難以使用，單靠訓練不容易維持效果。

*來源：本章 PDF 第 68–84 頁；以摘要及觀念解說重新整理。*

## 重要名詞

| 名詞 | 這篇的理解重點 |
| --- | --- |
| Phishing | 以偽裝訊息誘導使用者交付資訊或採取行動。 |
| Vishing | 以語音互動進行誘導。 |
| Impersonation | 假扮另一個人或可信角色。 |

## 理解用例（本文自擬）

有人自稱主管，以熟悉的語氣要求緊急匯款。即使聲音聽起來可信，也應透過既有聯絡方式核對，並依原有簽核流程處理；聲音相似不等於交易已獲授權。

這個例子用於解釋觀念，不是教材案例、實測結果或作者經歷。
