## 前言

BST 的效率取決於高度。依序插入 10、20、30 到 60，可能形成鏈狀結構，搜尋退化為線性成本。自平衡樹透過不同限制控制高度。

## 1. B-Tree

B-Tree 是多路搜尋樹，每個節點可包含多個已排序鍵值。鍵值把子樹分成不同範圍，所有葉節點維持相同深度。

簡報採用 order m 表示最多 m 個子節點，因此最多 m−1 個鍵值。非根內部節點至少有 `ceil(m/2)` 個子節點。其他教材可能用 minimum degree t 定義，不能直接混用公式。

新增可能讓節點分裂並向上傳遞；刪除則可能借用相鄰節點的鍵，或合併節點，保持容量與高度條件。

## 2. B+ Tree 與磁碟存取

B+ Tree 內部節點保存分隔鍵與子節點指標，資料項目或資料參照集中在葉節點；葉節點彼此連結，方便依序與範圍掃描。

要查詢鍵值介於 100 到 200 的資料，可以先找到第一個符合位置，再沿葉節點繼續掃描。

多個鍵放進同一節點可以提高分支數，減少樹高與頁面存取。但資料庫 page、作業系統 page 與磁碟 sector 是不同概念，頁面大小應以實際系統為準。

> 簡報第 9 頁用「頁面大小除以 row 大小」直接推導樹階數，是教學簡化。實際還有鍵、指標、頁面標頭與填滿程度；第 15 頁把資料庫名稱長度限制歸因於 B+ Tree，也不能當成普遍規則。

B+ Tree 的葉節點仍會受資料大小改變影響。內部節點也不只保存指標，不能說 row 改變後樹高一定不變。

## 3. AVL Tree

AVL 是平衡二元搜尋樹。以左高減右高定義 balance factor：

`BF = height(left) - height(right)`

每個節點 BF 都需落在 −1、0、1。插入或刪除後沿祖先更新高度，必要時旋轉。

| 失衡型態 | 修復 |
| --- | --- |
| LL | 對失衡節點右旋 |
| RR | 對失衡節點左旋 |
| LR | 先左旋左子，再右旋失衡節點 |
| RL | 先右旋右子，再左旋失衡節點 |

旋轉必須保持 inorder 的鍵值順序，只改變結構。AVL 搜尋、插入、刪除的最壞時間都是 `O(log n)`。

## 4. Red-Black Tree

紅黑樹用顏色條件控制高度：

- 每個節點為紅或黑，根為黑。
- NIL 葉為黑。
- 紅節點不能有紅色子節點。
- 從任一節點到其 NIL 後代的路徑，黑節點數一致。

黑高的計數需採一致慣例。這些條件讓搜尋、插入與刪除維持最壞 `O(log n)`，但不要求每個節點左右高度差至多 1。

## 5. 插入修復與旋轉

新節點依 BST 規則插入並設為紅色。若父節點為黑色，沒有紅紅衝突；若父為紅，查看叔叔：

| 狀態 | 常見處理 |
| --- | --- |
| 叔叔紅 | 父與叔叔改黑，祖父改紅，向上處理 |
| 叔叔黑，三角形 | 先旋轉父節點，轉成直線型 |
| 叔叔黑，直線型 | 旋轉祖父並重新著色 |

最後確保根為黑。這裡整理插入流程，刪除修復需要另外處理黑高變化。

簡報第 30 頁的旋轉敘述需要修正：左旋節點 5、讓 10 上升時，原本 10 的左子樹若是 8，應接成 **5 的右子樹**，因為 `5 < 8 < 10`。

## 6. 比較與心得

| 結構 | 核心設計 |
| --- | --- |
| B／B+ Tree | 多路分支，降低頁面存取，B+ 葉鏈適合範圍掃描 |
| AVL | 嚴格限制左右高度差 |
| Red-Black | 用顏色與黑高限制高度 |

我會先觀察資料存取環境，再比較平衡策略。記憶體中的單次比較與磁碟中的整頁讀取，成本模型不同。

旋轉最值得掌握的地方，是維持鍵值順序。只背 LL、RR 名稱很容易接錯子樹，先確認各區段大小關係，修復流程就更有依據。
