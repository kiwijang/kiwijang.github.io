## 前言

進階排序把問題拆成更容易處理的結構。這篇整理合併排序、堆積排序與快速排序，也補充簡報裡容易混淆的二元樹名詞。

## 1. Merge Sort 合併排序

先將陣列分成左右兩半，分別排序，再用兩個指標合併。每層合併總共處理 `n` 個元素，層數約 `log n`，得到 `Θ(n log n)`。

一般陣列版本需要 `O(n)` 輔助空間。終止條件應是長度小於等於 1，才能處理空陣列。

穩定版本在鍵值相等時先取左半邊元素，而且遞迴合併要保持原始左右順序。

> 簡報第 5 頁把右半邊傳在左半邊之前。雖然數值仍能排序，但相同鍵值的原始順序可能改變。若要穩定，應使用 `merge(sortedLeft, sortedRight)`。

## 2. 二元樹與 Max Heap

| 名詞 | 定義 |
| --- | --- |
| Binary Tree | 每個節點最多兩個子節點 |
| Complete Binary Tree | 最底層以外填滿，最底層由左向右排列 |
| Full Binary Tree | 每個節點有 0 或 2 個子節點 |
| Perfect Binary Tree | 內部節點都有兩個子節點，葉節點同深度 |
| Max Heap | 完全二元樹，父節點值不小於子節點 |

簡報將 Full 與 Perfect 的條件混用，整理時要區分。Heap 的左右兄弟不必排序，也不是 BST。

以 0 為起點的陣列索引，節點 `i` 的子節點是 `2i + 1`、`2i + 2`，父節點是 `floor((i - 1) / 2)`。

## 3. Heap Sort 堆積排序

先建立 Max Heap，將根節點與最後一個元素交換，縮小 heap 範圍，再向下調整根節點。重複後得到遞增陣列。

由最後一個內部節點 `floor(n / 2) - 1` 向上建立 heap，只需 `O(n)`，不是 `O(n log n)`。後面的逐次取出才累積成最壞 `O(n log n)`。

迭代版 heapify 可以使用 `O(1)` 額外空間；遞迴版還有最多 `O(log n)` 呼叫堆疊。

## 4. Quick Sort 快速排序

選擇 pivot，用 partition 將元素分配到兩側，再分別排序。

簡報的 Lomuto partition 使用最後一個元素當 pivot，完成後 pivot 在最終位置，但左右區段還沒完成排序。

平均或隨機化期望時間為 `O(n log n)`，最壞為 `O(n²)`。每次若只分出一個元素，遞迴會變得很深。隨機 pivot 可降低遭遇壞分割的機率，不能把最壞界改成保證線性對數。

## 5. 比較與心得

| 常見版本 | 平均／期望 | 最壞 | 額外空間 | 穩定 |
| --- | --- | --- | --- | --- |
| Merge | O(n log n) | O(n log n) | O(n) | 正確保留左右順序時是 |
| Heap，迭代 heapify | O(n log n) | O(n log n) | O(1) | 否 |
| Quick，原地 partition | O(n log n) | O(n²) | 平均 O(log n)，最壞 O(n) 堆疊 | 否 |

合併排序用記憶體換取穩定的效率，堆積排序控制最壞成本，快速排序則需要留意分割品質。

對我來說，最有幫助的是把排序看成「資料結構加上操作規則」。理解 merge 與 heapify，後面讀優先佇列就更容易連起來。
