## 前言

同樣能完成需求的程式，資料量變大後，執行成本可能差很多。這篇先整理演算法分析的基本觀念，後面比較搜尋與排序時，就有共同的判斷方式。

## 1. 演算法與複雜度

演算法是一組明確、有限的步驟。分析時先定義輸入規模 `n`，再估計操作次數如何隨 `n` 增長。

**時間複雜度**關心運算成本；**空間複雜度**關心記憶體需求。本文的空間比較以額外空間為主，遞迴呼叫堆疊也需要計算。

執行秒數會受硬體、快取、背景工作影響。複雜度適合比較成長趨勢，實測則用來確認特定環境的表現，兩者可以一起使用。

## 2. Big O、Big Ω 與 Big Θ

| 符號 | 意義 |
| --- | --- |
| Big O | 漸近上界 |
| Big Ω | 漸近下界 |
| Big Θ | 漸近緊確界，上下界同階 |

> **補充修正：Big O 本身不等於最壞情況。** 最好、平均、最壞情況的成本函數，都可以使用 Big O 描述。閱讀分析時要一起確認情況與假設。

例如 `13n³ + 6n + 7` 的主要成長項是 `n³`，因此可寫為 `Θ(n³)`，也屬於 `O(n³)`。常數與低階項在漸近分析中省略，但在小型資料的實測中仍可能影響結果。

## 3. 常見成長速度

| 複雜度 | 典型例子 |
| --- | --- |
| O(1) | 陣列依索引讀取 |
| O(log n) | 已排序陣列的二分搜尋 |
| O(n) | 掃描全部元素 |
| O(n log n) | 一般合併排序 |
| O(n²) | 比較所有元素配對 |
| O(2ⁿ) | 列舉全部子集合 |

兩個依序執行的線性迴圈，成本相加後仍是 `O(n)`。兩個巢狀迴圈若各自完整走訪 `n` 次，才得到 `O(n²)`。內層若逐次減半，也不能直接用「兩層迴圈」判斷。

## 4. 陣列與物件的操作

一般陣列索引存取是 `O(1)`，未排序搜尋是 `O(n)`。在中間插入或刪除可能搬移後面的元素，因此是 `O(n)`。

雜湊結構的查找常見期望成本為 `O(1)`，但依賴雜湊分布與碰撞處理。不能只看到物件語法，就假設所有操作都是固定成本。

## 5. 重點整理與心得

我會先問「資料量是什麼、哪個步驟重複最多」，再判斷值得優化的位置。例如把迴圈中的重複掃描改成查表，通常比換一種迴圈寫法更有意義。

這也提醒我：分析程式時，資料庫查詢次數、網路請求與資料搬移都需要一起考量。Big O 提供方向，實際瓶頸仍要靠量測確認。
