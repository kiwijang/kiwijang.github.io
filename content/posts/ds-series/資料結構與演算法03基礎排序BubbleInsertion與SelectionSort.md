## 前言

內建排序讓日常開發很方便，但自己理解排序流程，可以看出「相同 Big O」背後仍有不同的比較、搬移與交換成本。

## 1. Bubble Sort 氣泡排序

反覆比較相鄰元素，順序錯誤就交換。簡報採用由右往左掃描，讓較小的元素逐輪移到左側。

若一輪完全沒有交換，就可以提早結束。

> 簡報第 5 頁的偽程式碼沒有提早停止判斷，因此即使資料已排序，仍會做二次量級的比較。最好情況 `O(n)` 適用於加入「本輪是否交換」判斷的版本。

## 2. Insertion Sort 插入排序

把左側視為已排序區段，取出下一個值，將較大的元素向右移，再放進正確位置。這和整理手上的撲克牌很像。

```js
function insertionSort(array) {
  for (let j = 1; j < array.length; j++) {
    const key = array[j];
    let i = j - 1;
    while (i >= 0 && array[i] > key) {
      array[i + 1] = array[i];
      i--;
    }
    array[i + 1] = key;
  }
  return array;
}
```

只移動「嚴格大於」key 的元素，讓相同鍵值維持原有順序。資料已排序時，每輪只需確認一次，因此是線性成本。

## 3. Selection Sort 選擇排序

每一輪從未排序區段找到最小值，再與區段起點交換。

即使資料已排序，仍需找出剩餘區段的最小值，所以比較次數保持 `Θ(n²)`。交換次數是 `O(n)`，比不斷交換相鄰元素更少。

## 4. 複雜度與穩定性

| 常見版本 | 最好 | 平均 | 最壞 | 額外空間 | 穩定 |
| --- | --- | --- | --- | --- | --- |
| 氣泡，含提早停止 | O(n) | O(n²) | O(n²) | O(1) | 是 |
| 插入 | O(n) | O(n²) | O(n²) | O(1) | 是 |
| 選擇，以交換實作 | O(n²) | O(n²) | O(n²) | O(1) | 否 |

穩定排序讓相同鍵值保留原本的相對順序。用 `[2A, 2B, 1C]` 做選擇排序，第一輪交換後成為 `[1C, 2B, 2A]`，同為 2 的 A、B 順序改變了。

純整數看不出差別，但有姓名、日期等附加欄位時，就可能影響使用者看到的結果。穩定性要看實作方式，不能只看演算法名稱。

## 5. 重點整理與心得

我覺得插入排序最值得保留在工具箱：流程容易理解，對小量或接近排序完成的資料也有優勢。

挑選排序方式時，我會一起確認資料量、初始順序、額外記憶體與同分資料的順序需求。只有一個 Big O 數字，還不足以做完整選擇。
