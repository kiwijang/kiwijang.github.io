## 前言

資料結構決定哪些操作方便、哪些操作需要付出更多成本。這篇從鏈結串列開始，再整理堆疊、佇列與雜湊表。

## 1. Linked List 鏈結串列

每個節點保存值與下一個節點的連結。單向串列往下一個節點走，雙向串列額外保存前一個節點。

| 操作 | 陣列 | 單向鏈結串列 |
| --- | --- | --- |
| 依位置讀取 | O(1) | O(n) |
| 未排序搜尋 | O(n) | O(n) |
| 中間插入／刪除 | 搬移元素 O(n) | 已持有前驅節點時可 O(1) |
| 尾端新增 | 動態陣列攤銷 O(1) | 有 tail 時 O(1)，否則 O(n) |

> 「鏈結串列插入刪除很快」有前提。若需要先尋找位置，總成本仍可能是 `O(n)`；單向串列刪除節點通常也需要知道前驅。

節點連結增加記憶體需求，分散的配置也可能降低快取效率。鏈結串列與動態陣列都受可用記憶體限制，不能無限增長。

## 2. Stack、Queue 與 Deque

| 結構 | 規則 | 操作 | 用途 |
| --- | --- | --- | --- |
| Stack | LIFO，後進先出 | push、pop | 呼叫堆疊、復原 |
| Queue | FIFO，先進先出 | enqueue、dequeue | 工作排隊、BFS |
| Deque | 兩端皆可操作 | 前後端新增與移除 | 雙端處理 |

簡報的 Stack 練習最後剩下 `flour, milk`，大小為 2，頂端是 milk。

Queue 練習最後剩下 `phone, tablet, notes`，大小為 3，head 是 phone，tail 是 notes。

抽象規則與實作方式要分開看。若陣列佇列每次移除開頭都搬移元素，單次 dequeue 可能是 `O(n)`；環狀緩衝區可以避免這種搬移。

## 3. Hashtable 雜湊表

雜湊函數將 key 映射到桶位置。不同 key 可能得到相同位置，稱為 collision。

簡報介紹兩種方法：

- 除法法：`index = key mod m`。
- 乘法法：`index = floor(m × fractionalPart(key × A))`，其中 `0 < A < 1`。

字串可以依字元與位置組合計算，但只用字串長度或字元總和，容易讓不同內容落在相同位置。

## 4. 碰撞與負載因子

負載因子 `α = n / m`，其中 n 為元素數、m 為桶數。簡報使用 chaining，每個桶另存一組元素；此時 α 可以大於 1。

在均勻雜湊假設下，chaining 查找的期望成本為 `O(1 + α)`。維持 α 在常數範圍，就能有期望 `O(1)` 查找；最壞碰撞仍可能是 `O(n)`。

雜湊表可透過擴容與 rehash 處理資料增長，不必事先知道最終筆數。字串雜湊本身也可能需要與字串長度成比例的時間。

## 5. 補充與心得

雜湊表的雜湊與密碼儲存的雜湊有不同目標，不能用取餘數示範法儲存密碼。JavaScript 陣列也不能一概視為以雜湊表實作。

我的選擇方式會從主要操作出發：要依位置讀取、依 key 查找，還是按照加入順序處理？先弄清楚需求，才能理解資料結構的取捨。
