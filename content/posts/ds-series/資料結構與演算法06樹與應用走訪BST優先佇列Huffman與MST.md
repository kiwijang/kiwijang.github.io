## 前言

這份簡報的主題比較多，但共同核心是用節點與關係組織資料。樹能表達階層，也能支援搜尋、優先處理與編碼。

## 1. Tree 與走訪

無向樹是**連通且無環**的圖。有根樹則額外選定一個根。只有「無環」還不夠，互不相連的多棵樹稱為森林。

| 走訪 | 順序／工具 | 典型用途 |
| --- | --- | --- |
| BFS | 逐層，用 queue | 階層清單 |
| Preorder | 根、左、右 | 先處理父節點 |
| Inorder | 左、根、右 | BST 依序輸出 |
| Postorder | 左、右、根 | 先處理子節點再彙整 |

左右順序是二元樹的描述。一般多子節點樹的 inorder 需要另定規則。走訪必須處理空節點，BFS 也要考慮最寬一層的佇列空間。

## 2. Binary Search Tree

BST 要求左子樹全部鍵值小於目前節點，右子樹全部鍵值大於目前節點；重複鍵可採另定規則。這個限制套用到整棵子樹，不只是直接子節點。

依簡報序列 `5, 7, 1, 15, 9, 2, 14, 8, 3` 插入，inorder 會輸出 `1, 2, 3, 5, 7, 8, 9, 14, 15`。

搜尋與插入成本取決於高度 h，是 `O(h)`。樹平衡時 h 為 `O(log n)`，退化成鏈狀時則是 `O(n)`。平均對數表現需要插入分布等假設。

## 3. Priority Queue 優先佇列

優先佇列按照優先程度取出元素，常以 binary heap 實作。

| 操作 | 二元 heap |
| --- | --- |
| 查看最高／最低優先元素 | O(1) |
| 加入元素 | O(log n) |
| 取出最高／最低優先元素 | O(log n) |

Max Heap 或 Min Heap 取決於優先順序定義。優先度相同時若要保留先到先服務，可加入遞增序號當次要比較鍵。

> 簡報第 28 頁的父索引應為 `floor((i - 1) / 2)`，括號不可省略。第 29 頁取出元素應先保存根值，再交換、移除與調整，最後回傳保存值。

## 4. Huffman Encoding

Huffman 根據出現頻率建立前綴碼：任何字元的碼都不是另一字元碼的前綴，讓串接後的位元可以明確解碼。

1. 統計每個符號的頻率。
2. 用 Min Priority Queue 保存節點。
3. 反覆取出兩個最低頻率節點，合成新節點並放回。
4. 沿樹的左右分支配置 0、1，得到編碼。
5. 保存編碼資訊與有效位元長度，供解碼使用。

簡報的 `AAAABBB  C` 固定長度內容使用 30 bits，示範 Huffman 內容使用 19 bits；這不包含碼表、標頭與位元填補，因此不能直接當成完整檔案壓縮率。

## 5. Minimum Spanning Tree

連通、無向、加權圖的生成樹包含所有 V 個節點與 V−1 條邊。MST 在這些生成樹中選總權重最小者。

Prim 每次選一條跨越目前樹與外部節點的最輕邊。Kruskal 將邊依權重排序，加入不造成環的邊，可用 Union-Find 判斷。

簡報第 39 頁的 cyclic 應為 **acyclic**。若原圖不連通，結果是最小生成森林。MST 最小化總建置成本，不保證任意兩點的路徑都是最短。

## 6. 重點整理與心得

BST、Heap 與 Huffman Tree 都是樹，但維護的條件不同。把條件寫清楚，比只看形狀更能理解它們。

我也會特別區分「最短路徑」與「總連線成本最低」。需求目標不同，即使輸入都是圖，也不能直接使用同一個演算法。
