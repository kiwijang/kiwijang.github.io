## 前言

有些問題仍需要探索大量候選，但可以提早排除沒有希望的分支。這篇整理 backtracking、branch and bound，以及利用已知匹配資訊的 KMP。

## 1. Backtracking 回溯

回溯逐步建立候選解，發現目前選擇違反限制時，就撤銷並嘗試其他選擇。

```text
search(state):
  若已完成:
    保存答案
    return
  對每個可選項:
    若違反限制: continue
    作出選擇
    search(nextState)
    撤銷選擇
```

排列問題可以記錄哪些元素已使用；撤銷時要還原狀態。若資料有重複值，還需避免重複輸出同一排列。

## 2. N Queens

每列放一個皇后，檢查欄與兩條對角線是否衝突。對位置 `(row, col)`，可用 `col`、`row - col`、`row + col` 三組集合紀錄。

一旦某列沒有可放位置，就不用繼續產生後面的棋盤。這是提早剪掉不可行的部分解，並不保證把所有問題的最壞成本降成多項式。

## 3. 0/1 Knapsack

每件物品只有「拿」與「不拿」兩種選擇，直接列舉可達 `2ⁿ` 個子集合。

回溯可剪掉超重分支。若重量與容量為整數，也可以用 `dp[i][w]` 表示前 i 件、容量 w 的最佳收益。

DP 的 `O(nW)` 依賴容量數值 W，W 的二進位輸入長度只有約 log W，所以這是偽多項式時間，不能據此宣稱一般背包已得到多項式時間解法。

## 4. Branch and Bound 分支限界

保存目前最佳可行解，並估計每個分支可能達到的最好結果。

最大化問題若某分支的收益上界不大於目前最佳值，就可以剪掉。背包可用允許分割物品的收益當作上界，因為放寬限制後不會比 0/1 最佳收益更小。

| 方法 | 常見剪枝依據 |
| --- | --- |
| 回溯 | 部分解已違反限制 |
| 分支限界 | 即使樂觀估計，也無法改善目前最佳解 |

> 簡報把 branch and bound 與 BFS 綁定，這是過度簡化。它也能採 DFS 或依界限選下一個節點。回溯也不限於決策問題，可以找一個解或列舉全部解。

上界必須足夠樂觀。若低估了可得收益，可能錯誤剪掉真正最佳解。只需一個最佳解時可在相等時剪枝，若要全部最佳解，則需另處理相等分支。

## 5. KMP 字串匹配

KMP 在匹配失敗時，利用 pattern 的最長真前綴／後綴資訊，決定已匹配部分可以保留多少。

例如 `ABABAC` 的 LPS 表為 `[0, 0, 1, 2, 3, 0]`。匹配失敗時縮短 pattern 的匹配長度，來源字串的指標不用倒退重掃。

建立 LPS 為 `O(m)`，搜尋為 `O(n)`，總時間 `O(n + m)`，額外空間 `O(m)`。這是對簡報第 9 頁概念的補充說明，並非原簡報提供的完整實作。

## 6. 重點整理與心得

剪枝讓搜尋更有效率，但要先確定剪枝條件不會漏掉有效解。KMP 則提醒我，之前比較成功的資訊也能成為下一步的依據。

這些方法共同值得學的地方，是避免把已經知道的事丟掉，讓程式再從頭計算。
