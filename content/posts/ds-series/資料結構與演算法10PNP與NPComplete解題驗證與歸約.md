## 前言

這章問的是：能快速檢查答案的問題，是否也能快速找到答案？理解時需要先區分決策問題與最佳化問題，也要避免把 NP 誤認成「一定很慢」。

## 1. P 與 NP

P 是能以確定性演算法在多項式時間內解決的決策問題類別。

NP 是 YES 答案存在多項式長度證書、且能在多項式時間驗證的決策問題類別。可以把證書理解為候選解及其必要資訊。

**P 包含於 NP**，因為能快速解題，也能快速驗證。NP 的全名是 nondeterministic polynomial time，並非 non-polynomial。

截至 2026-10-14，Clay Mathematics Institute 仍將 P versus NP 列為未解問題。[來源](https://www.claymath.org/millennium/p-vs-np/)

多項式時間也不直接等於幾秒內完成：次方很高、常數很大或輸入巨大，仍可能不實用。

## 2. Reduction 歸約

`A ≤p B` 表示可以在多項式時間，把 A 的輸入轉成 B 的輸入，並保留 YES／NO 答案。

如果 B 有多項式解法，A 也可以先轉換，再使用 B 的解法。因此 B 至少和 A 一樣難。

證明新問題 B 是 NP-Complete 時：

1. 證明 B 屬於 NP。
2. 從已知 NP-Complete 問題 A，歸約到 B。

> 簡報最後一頁的方向需要修正。將自己的問題歸約到已知困難問題，不能單憑這點證明自己的問題很難；證明困難度需要從已知困難問題歸約到自己的問題。

## 3. NP-Hard 與 NP-Complete

| 類別 | 定義 |
| --- | --- |
| NP-Hard | 每個 NP 問題都可多項式歸約到它 |
| NP-Complete | 同時屬於 NP 與 NP-Hard |

NP-Hard 不一定屬於 NP。NP-Complete 問題可彼此多項式歸約；若任一個得到多項式時間解法，就能推出 P = NP。

簡報「NP-Complete 不能歸約到 NP 問題」的說法不正確，因為 NP-Complete 自己就在 NP 裡。以上定義與方向可參考 [MIT 複雜度講義](https://ocw.mit.edu/courses/6-006-introduction-to-algorithms-spring-2020/fda666a4db1dc65b3d71be08115502bd_MIT6_006S20_lec19.pdf)。

## 4. 常見問題的版本

| 主題 | 決策問題例子 |
| --- | --- |
| SAT | 是否存在使布林式成立的指派？ |
| Subset Sum | 是否有子集合總和為 K？ |
| Hamiltonian Cycle | 是否有經過每個頂點恰一次並回到起點的環？ |
| TSP | 是否有總長度不超過 K 的巡迴？ |
| Vertex Cover | 是否有大小不超過 K 的頂點覆蓋？ |
| Clique | 是否有至少 K 個頂點的完全子圖？ |

「找最短 TSP 路線」是最佳化版本，通常稱 NP-Hard；談 NP-Complete 時應明確指決策版本。Hamiltonian path 不要求回到起點，cycle 則需要。

簡報的集合 `{10, 15, 9, 12, 16, 21, 3, 6}`，可以用 `15 + 9` 或 `21 + 3` 得到 24。

## 5. 3-SAT 到 Clique 的概念

對每個子句的文字建立頂點。不同子句中、互不矛盾的文字之間連邊。若有 k 個子句，存在大小 k 的 clique，就對應每個子句選出一個可相容為真的文字。

這說明歸約如何將「布林指派」轉成「圖結構」，而不是把兩個問題的程式碼直接換名字。

## 6. 補充修正與心得

NP-Complete 不代表只剩原始暴力法。剪枝、DP、特殊結構與近似方法仍可能處理實務個案，只是不能據此保證一般輸入的多項式精確解。

一般 N 皇后「找一組解」也不能因回溯很慢就被當成 NP-Complete 的證明。整數分解的困難性、量子計算與 RSA 更是不同議題，簡報的延伸敘述不足以支持「所有密碼都會被破解」這種結論。

這章讓我更重視問題版本與證明方向。遇到難題時，先界定是否要精確最佳解、規模多大、能否接受近似，再決定實作策略。
