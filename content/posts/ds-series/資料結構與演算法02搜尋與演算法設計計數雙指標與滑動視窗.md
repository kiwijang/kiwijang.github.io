## 前言

這份簡報讓我注意到：很多優化來自保留已經算過的資訊。計數表、雙指標與滑動視窗，都是用資料的特性減少重複工作。

## 1. 線性搜尋與二分搜尋

| 方法 | 前提 | 最好 | 平均／最壞 |
| --- | --- | --- | --- |
| 線性搜尋 | 可逐一比較 | O(1) | O(n) |
| 二分搜尋 | 已排序且可有效隨機存取 | O(1) | O(log n) |

線性搜尋從頭檢查，找不到回傳 `-1`。簡報第 5 頁的平均公式排版容易誤讀；平均約 `n/2` 次比較仍是線性成長。

二分搜尋每次排除一半候選範圍。若為了單次搜尋先排序，排序成本也要算進去。

```js
function binarySearch(array, target) {
  let left = 0, right = array.length - 1;
  while (left <= right) {
    const middle = left + Math.floor((right - left) / 2);
    if (array[middle] === target) return middle;
    if (array[middle] < target) left = middle + 1;
    else right = middle - 1;
  }
  return -1;
}
```

## 2. 計數表 Frequency Counter

比較 `abba` 與 `abab` 是否包含相同字元與次數，可以先記錄每個字元出現幾次，再扣掉另一字串的次數。期望時間為 `O(n + m)`，額外空間與不同字元數有關。

交集問題也可以用集合減少重複搜尋，但要先確認：結果要保留重複項目嗎？順序是否重要？集合交集與多重集合交集的需求不同。

## 3. 雙指標 Two Pointers

對已排序陣列尋找平均為 `1.5` 的配對，相當於找總和為 `3` 的兩個數。

從左右兩端開始：總和太小就移動左指標，太大就移動右指標。排序讓移動方向有依據。簡報的例子可找到 `(-11, 14)`、`(0, 3)`、`(1, 2)`。

回文檢查則比較左右字元；子序列檢查可用一個指標掃描來源，另一個指標追蹤已匹配的位置。這裡的 pointer 指的是索引位置，不一定是 C 的記憶體指標。

## 4. 滑動視窗 Sliding Window

固定長度的連續區段，可以先算第一個視窗的總和，之後每次減去離開的元素、加上新元素。這讓重算每個區段的 `O(nk)` 降為 `O(n)`。

簡報的長度 3 範例，最大和是 `12`，最小和是 `-28`。

可變視窗則包含「總和至少達到目標的最短子陣列」與「最長不重複字元子字串」。

> 最短子陣列的簡單收縮策略依賴正數條件。若含負數，縮小視窗不一定讓總和下降，不能直接沿用同一套判斷。

最大乘積視窗還要特別處理 0，避免以除法移除元素時除以零。

## 5. 遞迴 Recursion

遞迴需要終止條件，以及每次呼叫如何朝終止條件前進。陣列攤平與樹走訪很適合用遞迴描述，但深度過大可能耗盡呼叫堆疊。

費氏數列的直接遞迴會反覆求解同一個子問題，後面的動態規劃會處理這個問題。

## 6. 重點整理與心得

我會先確認資料是否排序、區段是否連續、是否能重用前一次的結果，再決定技巧。這比記住題目的標準答案更容易應用到新問題。

實作時，空輸入、重複值、找不到答案與視窗長度超過陣列，都值得先列入邊界條件。
