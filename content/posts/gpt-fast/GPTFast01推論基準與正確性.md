## 算得快，還需要知道算的是同一件事

若把輸出長度減半，生成通常會變快；若刪掉一半前文，也可能變快。但這些都改變了任務。研究推論加速，要先說清楚模型、輸入、輸出規則和比較標準。

前一系列的 [LLM 04：組裝 GPT](../llm-from-scratch/LLM04從零組裝GPT模型.md) 說明模型輸出 vocabulary logits；[LLM 05：預訓練與生成](../llm-from-scratch/LLM05預訓練與文字生成.md) 則區分權重更新和解碼。這次優化的是既有模型的前向與生成流程，不靠重新訓練來證明程式正確。

## 1. 「正確」至少有三種要求

| 層次 | 想保留的東西 | 常見例子 | 驗證方式 |
| --- | --- | --- | --- |
| 數值近似等價 | 相同條件下的 logits／hidden states | KV cache、核心融合、編譯 | 固定 token 前綴，檢查誤差 |
| 分布等價 | 輸出的機率分布 | 正確的推測採樣演算法 | 演算法推導與小分布驗證 |
| 品質在容許範圍 | 任務效果仍符合需求 | INT8／INT4 權重量化 | 獨立資料上的品質指標 |

第一類通常不要求逐 bit 相同，浮點運算重排會影響捨入。第二類也不保證同 seed 產生同一句話，因為演算法可能消耗不同數量的亂數。第三類則確實改變了近似模型，必須交代品質差異。

不能把「我看了一段回答，感覺差不多」當作這三類改動共同的驗證標準。

## 2. 先建立可信任的參考路徑

基準需要固定 checkpoint、模型設定、tokenizer、BOS／EOS、prompt token IDs 和位置定義。若是 chat 模型，還要固定模板。單純使用同一段可見文字，未必代表實際輸入一致。

這接續 [LLM 02：Token 與 Embedding](../llm-from-scratch/LLM02文字資料Token與Embedding.md)：token ID 是查表索引，換 tokenizer 可能改變全部索引意義。推論也不是只載入權重就完成，模型結構必須和它相容。

有了參考模型後，先比較相同完整前綴下的 next-token logits，再比較最佳化路徑。不要一開始就讓兩邊自由生成數百字，因為第一個不同 token 會讓後續輸入全面分岔，難以定位錯誤。

## 3. 逐步比較，比只比較最後字串更有用

可以先準備固定序列 `a, b, c, d`：參考路徑每次完整輸入前綴；快取路徑依序 prefill 與 decode，但餵入的 token 都使用這份固定序列。

```text
參考：forward(a, b, c) → 比較 c 位置的 logits
快取：cache(a, b) + forward(c, position=2) → 同一組 logits
```

這樣能把快取位置或遮罩錯誤，和抽樣造成的差異分開。誤差可以記錄最大絕對值、平均值和相對誤差；接近零的分母需要保護，也要明訂 NaN／Inf 的處理。

容忍度依 dtype、層數與參考精度決定，不能直接抄一組數字套到所有模型。即使 logits 很接近，若最高分兩個候選幾乎平手，greedy 結果仍可能不同。

## 4. 推論模式有兩個不同開關

`model.eval()` 控制 dropout 等層的行為；`torch.no_grad()` 或 `torch.inference_mode()` 控制 autograd 記錄。進入 inference mode 不會自動把模型切成 eval。

對無需梯度的推論，兩者應各自確認。gpt-fast 的載入流程會回傳 eval 模型，生成函式也停用梯度；這些是推論流程的一部分，不是量化或編譯帶來的語言能力。[原始載入與生成程式](https://github.com/meta-pytorch/gpt-fast/blob/6ecad9b5b6b987d17ac4303965545873d0192086/generate.py)

## 5. 每次只加入一種改動

合理的比較順序是參考前向、KV cache、編譯、量化，再視需求加入推測解碼或多卡。每一步都保存品質和效能紀錄，才能知道某個差異從哪裡出現。

例如快取版已算錯，後面編譯只會更快地重複同一個錯誤。量化造成小幅 logit 偏移，也不能反過來掩蓋快取漏掉一個 token 的問題。

gpt-fast 快照本身使用 Llama 類架構；前一系列以 GPT-2 類設計教學。兩者不是相同 checkpoint，不能直接把它們的輸出互相比對來判斷加速是否正確。架構差異會在第五篇展開。

## 6. 練習：為改動選對驗證方法

試著判斷三個情境：把前文 K、V 存起來、把權重改存 INT4、讓小模型先提案再驗證。它們分別應先檢查數值、品質與分布條件。

每個實驗先寫一句話：「這次改動預期保留什麼，允許什麼差異？」能回答這句，後面的速度數字才有意義。
